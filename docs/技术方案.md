## 1. 方案总览

在产品设计文档第 7 节选型基础上，补全实现层面的关键决策（数据访问、密码安全、测试体系、性能纪律），形成可执行的完整技术栈：

| 层次 | 选型 | 关键补充 |
|---|---|---|
| 前端框架 | Vue 3（组合式 API）+ Vite | — |
| 状态/路由 | Pinia + Vue Router | — |
| 可视化 | ECharts 5 | 热力图用 `calendar` + `heatmap` |

| 测试 | 前端 Vitest ｜ 后端 Supertest | 遵循 AGENTS.md：改动必配测试 |

## 3. 前端方案

### 3.1 目录结构（M1 脚手架基线）

```
liujing/
├─ frontend/
│  ├─ src/
│  │  ├─ api/            # fetch 封装 + 各模块接口
│  │  ├─ stores/         # Pinia: user / session / scene / yuejian
│  │  ├─ router/
│  │  ├─ scenes/         # 6 个 Canvas 场景组件 + 公共粒子引擎
│  │  │  ├─ engine.js    # rAF 循环、resize、粒子基类（非响应式）
│  │  │  └─ sakura/ star/ frost/ firefly/ deepsea/ autumn/
│  │  ├─ views/          # Login / StudyRoom / Stats / Settings
│  │  ├─ components/     # 番茄钟、任务清单、月见对话面板等
│  │  └─ utils/
│  └─ vite.config.js
├─ backend/
│  ├─ src/
│  │  ├─ routes/         # auth / sessions / stats / ai
│  │  ├─ dao/            # mysql2 手写 SQL
│  │  ├─ middleware/     # jwt 闸、错误处理、校验
│  │  ├─ ai/             # 语库(保底) + llm代理(增强) + prompt模板
│  │  └─ app.js / server.js
│  └─ tests/             # Supertest 接口测试
└─ .env                  # DB_* / JWT_SECRET / LLM_API_KEY（不进 git）
```

### 3.2 关键实现纪律

1. **Canvas 粒子数据禁止响应式化**。粒子坐标、速度等每帧变更的数据存放在普通 JS 对象/数组中，由 `engine.js` 的 requestAnimationFrame 循环直接操作 Canvas API 绘制。Vue 响应式只管理"当前场景 ID、是否全屏、音效开关"这类低频 UI 状态。原因：Proxy 代理数千粒子对象会把帧率从 60fps 拖到个位数。
2. **场景组件化协议**：每个场景导出统一接口 `{ init(ctx, w, h), update(dt), resize(w, h), destroy() }`，由 `engine.js` 统一调度，实现 6 场景无感切换（切场景 = destroy 旧 + init 新，粒子淡出可选）。
3. **倒计时权威源在前端 `session store`**，用时间戳差值计算而非累加 setInterval 次数，避免后台节流导致计时漂移；标签页标题同步走 `watch` + `document.title`。
4. **ECharts 按需引入**（`echarts/core` + 手动注册 Calendar/Heatmap 等组件），控制打包体积。

## 4. 后端方案

### 4.1 鉴权与安全

- 注册：`bcryptjs.hash(password, 10)` 后入库；登录：`bcrypt.compare` 校验。
- JWT：登录成功签发 `expiresIn: 7d` 的 token；除 `/api/auth/*` 外所有路由经 JWT 闸中间件。
- Key 管理：`JWT_SECRET`、数据库连接、大模型 API Key 全部走 `.env`，`.env` 写入 `.gitignore`。
- 校验：路由层对入参做类型/长度校验（手写小工具函数即可，不引重型校验库）。

### 4.2 数据库设计（3 张核心表）

```sql
-- 用户表
users        (id PK, username UNIQUE, password_hash, nickname,
              created_at, prefs JSON)   -- 默认场景/音效/时长等偏好

-- 自习记录表（P0 数据持久化核心）
study_records(id PK, user_id FK→users, scene VARCHAR(20),
              started_at, ended_at, duration_sec INT,
              tasks_total INT, tasks_done INT,
              created_at)
              INDEX(user_id, started_at)   -- 统计聚合走这条索引

-- 任务表（可选并入 study_records 的 JSON 字段，P0 先用 JSON，量大再拆表）
```

统计口径约定：`duration_sec` 以前端提交的起止时间戳差值回算校验（容忍 ±60s），防止前端计时异常产生脏数据。

### 4.3 API 清单（P0 范围）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/auth/register | 注册（用户名+密码） |
| POST | /api/auth/login | 登录 → `{ token, user }` |
| GET/PUT | /api/auth/profile | 读取/更新资料与偏好 |
| POST | /api/sessions | 上报一次自习记录 |
| GET | /api/sessions | 分页查询历史记录 |
| GET | /api/stats/summary | 日/周/月时长、连续打卡天数 |
| GET | /api/stats/heatmap | 专注时段热力图数据 |
| POST | /api/ai/chat | 月见对话（内部先走语库，配置 Key 后走 LLM） |

## 5. 月见（AI 陪伴智能体）实现方案

双轨架构，`/api/ai/chat` 内部路由：

1. **保底轨（默认开启，零外部依赖）**：`ai/library.js` 语库，按事件类型（开工/收工/久坐/连续打卡/任务全清/断签回归）+ 场景名检索固定文案，随机去重取用。无网络、无 Key 时系统完整可用。
2. **增强轨（`.env` 配置 LLM_API_KEY 后自动启用）**：
   - `ai/prompt.js` 组装 system prompt：月见人设（温柔安静、克制不聒噪）+ 上下文注入（今日时长、连续天数、任务完成率、当前场景）；
   - 对话历史保留最近 6 轮，超限裁剪，控制 token 预算；
   - **SSE 流式输出**（M4 加分项，约 30 行实现）：响应以 `text/event-stream` 返回，前端打字机效果渲染。
3. 模型选型：DeepSeek 或阿里百炼（国内直连、有免费额度、单次成本低）；更换模型只改 `ai/llm.js` 一个文件的 baseURL/model 参数。

## 8. 明确不做的事（防蔓延）

- ❌ Three.js / WebGL / shader——2D 粒子足够，答辩风险低
- ❌ ORM（Prisma/Sequelize）——3 张表手写 SQL 更清晰可控
- ❌ TypeScript——单人毕设、代码量可控，JS + JSDoc 注释即可（如后续想升级再议）
- ❌ 微信小程序/PWA/WebSocket 实时同桌——属 P2 展望，写入论文即可
- ❌ 前端直连大模型 API——Key 只存在于后端
